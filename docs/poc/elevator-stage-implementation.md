# エレベーターステージ PoC 実装メモ

## 実装範囲

- 画面構図は `docs/art/references/stages/elevator/elevator-stage-v1-approved.png` をそのまま基準にする。
- PixiJS が背景、左右の扉、時間進行、描画更新を担当する。
- `ElevatorStageController` が描画から独立して扉、外側 NPC、内側 NPC、メモリ内イベントを管理する。
- URL の `?route=elevator` で直進、既定の `?route=side` で横通路へ分岐する開発確認ができる。
- 画面右上の控えめな `↻` は、同じ場面を初期状態から再確認する開発用操作である。

## アセット接続状況

本番用 `.riv` はリポジトリに存在しないため、接続済みとは扱わない。

`CharacterAdapter` を本番 Rive ランタイムとの接続境界として定義した。人物を SVG / CSS で描き直さず、矩形cropによる二重表示も避けるため、現在は正式採用画像内の静止人物を明示的な開発用プレースホルダーとして維持する。人物の動的描画は正式な透過人物素材またはRiveリグの配置待ちである。

本番 Rive 素材が届いたら、各人物の adapter 実装を Rive 用実装へ差し替え、`gazeX`、`headTurn`、`bodyTurn`、`speed`、`tension` の連続値を正式 State Machine / Data Binding へ接続する。

## 現時点の制約

- 正式採用画像は構図基準とプレースホルダー素材のために参照しており、最終的なレイヤー分解済み背景素材ではない。
- 外側 NPC の予兆はロジック値まで。視線、顔、上半身を高品質に読み取れる最終演技には正式な透過人物素材または Rive リグが必要。
- 内側 NPC の視線・重心値は実装済みだが、正式 Rive リグがないため画面上の連続演技への接続は未完了。
- Android 実機での可読性、タッチ領域、フレームレートは人間による確認が必要。
