# エレベーターステージ 3ボタン版 PoC アセット分解

## 位置づけ

本資料は、正式基準画像の空気感と構図を保ちながら、2026-08-20 に指定された「開ける / 閉める / 様子を見る」の3つを同格の明示操作として置く本番画面候補を、現在の PixiJS PoC へ接続するための実装メモである。

これは最終アート完成宣言ではない。元画像に隠れた領域を推測して描き足さず、人物を描き直さない。

## 実装用レイヤー

```text
public/assets/stages/elevator/
├─ doors/
│  ├─ door-left.svg
│  └─ door-right.svg
└─ ui/
   ├─ button-default.svg
   ├─ button-active.svg
   └─ button-disabled.svg
```

- シーンの暫定ベースには、既存の正式基準画像 `docs/art/references/stages/elevator/elevator-stage-v1-approved.png` を直接参照する。PRへ同一バイナリを重複追加しない。内装、廊下、操作盤に加えて静止人物も含むが、最終背景1枚として固定する意図ではなく、正式な透過人物素材が未提供の期間だけ構図を崩さないために使う。
- `doors` は左右独立の PoC 用パネル。PixiJS がそれぞれを動かし、開口部マスクでクリップする。人物アートではない。
- `ui` は文字を焼き込まないボタンプレート。ラベルとアイコンはアクセシビリティ、ローカライズ、押下状態のため HTML で重ねる。3操作に正解・危険を示す色差は付けない。

## 入力とロジックの境界

- `ElevatorStageController`: 自然閉鎖、早期閉鎖、再開放、NPCの観察サイン、イベント時刻を管理する。
- `ElevatorStageView`: ベース画像と独立した左右扉のみを描画する。
- `main.ts` / HTML UI: 3ボタンのポインター入力を controller へ渡す。「様子を見る」は世界を止めず、`explicit_non_intervention` を記録する。
- `CharacterAdapter`: 将来の正式 Rive 実装との境界。現在のリポジトリに `.riv` はなく、接続済みではない。

## 暫定箇所と正式差し替え

| 現在の暫定素材 | 将来必要な正式素材 |
| --- | --- |
| 既存の正式基準画像を直接参照する人物入りベース | 人物なし背景（内装 / 廊下 / 操作盤。必要なら前景も分離） |
| ベース画像内の静止人物 | ひかえめくん、内側NPC、外側NPCの透過素材または承認済み Rive リグ |
| 金属グラデーションの左右扉 | 正式画風で開口部の高さ・光源に一致した左右扉 |
| 汎用3状態ボタンプレート | 正式候補画面から書き出した default / pressed / disabled のボタン素材 |

正式素材受領後も controller の変更は不要とし、view と `CharacterAdapter` 実装だけを差し替える。

## スマホ確認項目

1. 親指操作で3ボタンを押し分けられるか。
2. UIがひかえめくん、内側NPC、扉の隙間を過度に隠さないか。
3. 押下中も廊下奥の外側NPCを観察できるか。
4. 「様子を見る」が無効・補助扱いではなく、同格の判断に見えるか。
5. セーフエリア付き端末でラベルとボタンが欠けないか。
