# Rive + PixiJS PoC仕様 v0.2

## 1. 目的

本編を作る前に、**ChatGPT + Rive + PixiJS + Codex** の構成で、少ない人手でも魅力的で滑らかな2Dキャラクター表現を作れるか検証する。

PoCはゲーム完成が目的ではありません。

## 2. 検証対象

最初はキャラクター1人だけ。

対象：メインキャラクター「ひかえめくん」。

正式仕様：

- `docs/character-spec-player.md`
- `docs/rive/player-character-parts-v1.md`

## 3. 必須表現

PoCでは以下を実現する。

- 自然な呼吸
- 自然なまばたき
- 視線移動
- 顔の小さな傾き
- 少し困る
- より困る
- 手を少し上げる
- 安心して元へ戻る

状態は差分画像の瞬間切替ではなく、連続的に変化すること。

## 4. ゲーム側からの制御

PixiJS / JavaScript側から少なくとも1つの連続値を変更し、Riveキャラクターの反応へ反映する。

例：

`stimulus = 0.0 ... 1.0`

この値から、

- eyeSquint
- browTension
- headTurn
- bodyLean
- armRaise

などを連続制御する。

PoC上では開発確認用スライダーを置いてよい。

これは本編UIではなく、技術検証専用。

## 5. 合格条件

以下をすべて満たすことを目標とする。

1. 以前のSVG/CSS人物より明らかに魅力的に見える
2. 静止中でも完全な静止画に見えない
3. 0〜100%の中間表情が自然
4. 目・眉・頭・身体・腕の変化がバラバラに見えない
5. Androidスマホで滑らかに動く
6. タッチ操作に対する反応遅延が気にならない
7. この制作方法を複数キャラクターへ再利用できる見込みがある
8. ユーザーの手作業をキャラクターごとに大量発生させない

## 6. 不合格条件

以下のいずれかが強い場合は、本編へ進まず方式を再検討する。

- 関節が人形のように固い
- パーツの境界が目立つ
- 元絵の魅力が大きく失われる
- スマホで重い
- 新キャラクター追加のたびに大量の手作業が必要
- Rive作業がChatGPT/Codex主体の運用に適さない

## 7. 技術構成

### Rive
- キャラクターリグ
- ボーン / メッシュ
- 表情・姿勢アニメーション
- State Machine / Data Binding等による制御

### PixiJS
- PoC画面
- 入力
- 開発用コントロール
- 更新ループ
- 将来的な背景・小物・ゲーム状態管理

### ChatGPT
- キャラクター仕様
- アート仕様
- 画像生成
- パーツ構成設計
- レビュー

### Codex
- PixiJSセットアップ
- Rive Runtime接続
- 値連携
- テスト
- ビルド
- デプロイ
- 可能な自動化

## 8. コスト方針

- PoC段階ではRive Freeを優先する
- 有料契約はPoCの品質を確認してから判断する
- 目安は月10USD前後まで
- 高価な専用ツールを前提にしない

## 9. 自動化方針

最終的には、ユーザーの役割を主にレビューへ寄せる。

理想フロー：

1. ChatGPTが仕様とアートを作る
2. キャラクター素材を規格化する
3. Codexが素材最適化・ゲーム組み込みを行う
4. 自動ビルドでPreviewを作る
5. ユーザーがスマホで確認し、OK/NGを返す

Rive内で毎キャラクター手動リグが必要になる場合は、テンプレートリグや画像差し替えによる再利用を優先検討する。

## 10. PoCで作らないもの
