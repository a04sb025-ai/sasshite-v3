# 「察して。」ビジュアルガイドライン v0.1

## 1. 目的

このゲームの絵は「豪華さ」より、**一瞬で状況・人間関係・視線・違和感が読めること**を優先します。

参考にするのは、少ない線と色で人物関係や空気感を伝えるソーシャルパズル系の読みやすさです。ただし既存作品のキャラクターデザインや構図をそのまま模倣しません。

## 2. 基本スタイル

- 2D
- フラット
- シンプル
- 記号的
- 親しみやすい
- 余白がある
- スマホで読みやすい

高精細なテクスチャや複雑な陰影は原則不要です。

## 3. 情報の優先順位

1. 主人公とNPC
2. 操作・状況理解に必要な小物
3. 関係性を説明する背景要素
4. 装飾

装飾が1〜3の読みやすさを邪魔してはいけません。

## 4. 色

### 主人公
淡い水色〜青系。

### NPC
白〜薄いグレーを基調とする。

### 線
濃いグレー〜黒。

### 背景
人物より低コントラスト。

赤＝不正解、緑＝正解のようなゲーム的意味付けを常用しません。

## 5. 線

- キャラクター外周：最も強い
- 顔・服の内部線：外周より少し弱い
- 小物：中程度
- 背景：最も弱い

線幅の差で視線誘導します。

## 6. キャラクター

- 約2.6〜2.8頭身を基本とする
- 顔はシンプル
- 表情差は眉・目・口・顔角度・姿勢で作る
- 感情を絵文字のように誇張しすぎない
- 人物同士の距離・身体の向き・目線を特に丁寧にする

主人公の詳細は `docs/characters/hikamekun.md` を参照。

## 7. NPC

NPCは単なる背景ではありません。

ゲームのフィードバック装置として、次の変化を読み取れるようにします。

- 視線
- 顔の向き
- 肩の上がり下がり
- 身体の傾き
- 手の位置
- 人との距離
- 動作の速度
- 一瞬の間

ただし、困り状態をアイコンやゲージで直接説明しないことを基本とします。

## 8. 背景

背景は「場所」と「問題の文脈」を説明するために使います。

例：電車なら、

- 座席
- 窓
- 吊り革
- ドア

など、その場所だと認識するのに必要な要素だけで成立させます。

不要な広告・模様・小物を大量に置かないでください。

## 9. UI

UIは最小限にします。

避ける：

- NPC快適度ゲージ
- 好感度ハート
- 正解位置表示
- 「上げすぎ」「下げすぎ」などの答えに近い説明
- 大きなSUCCESS表示
- 常時表示される長文チュートリアル

必要な操作は、できる限り画面上の物を直接触る設計にします。

## 10. アニメーション

「ヌルヌル」は派手な動きの量ではなく、自然な連続性で作ります。

常時：

- 呼吸
- まばたき
- 微小な重心移動
- わずかな視線移動

状況反応：

- 目を細める
- 顔をそむける
- 肩が固くなる
- 手を伸ばしかける
- 少し距離を取る
- 安心して姿勢が戻る

0/1の画像切替ではなく、中間状態を持たせます。

## 11. Rive / PixiJS分担

### Rive
- 主人公・重要NPCのリグ
- 顔・身体の連続変化
- アニメーションブレンド

### PixiJS
- 背景
- 小物
- 操作
- 光
- パーティクル
- 場面の状態管理
- Riveキャラクターへの値渡し

## 12. Source of Truth

採用されたキャラクター設定画や基準ゲーム画面は、今後 `references/` 配下に保存し、関連するMarkdownから参照します。

基準画像と実装が食い違う場合、実装を簡略化する前に仕様を確認します。
