# 「察して。v3」最初の1ステージ候補 v1.0

## 1. 目的

最初から大量のステージを作らず、**『察する行為そのものがゲームとして面白い』ことを1ステージで証明する**。

評価軸：

1. 初見で状況を理解しやすい
2. NPCを見る必要がある
3. 1タップで終わらない
4. 加減またはタイミングがある
5. ミスから修正できる
6. NPCの演技がゲームUIになる
7. いたずら・別解がある
8. 再プレイしたくなる
9. スマホ操作と相性が良い
10. 海外でも意味が通じやすい

---

## 2. 候補A：エレベーター「もう一人、来る？」

### 状況

主人公はエレベーターの操作盤付近にいる。

扉が閉まり始める直前、廊下の奥から人が近づいてくる。一方、エレベーター内には時計を気にする人、荷物を持った人などがいる。

### 主操作

- 開ボタンを長押しする
- 離す
- 必要なら主人公の立ち位置を少し動かす

### 察する対象

- 近づいてくる人の速度・視線・身体の向き
- 本当にこのエレベーターへ来るのか
- 中の人の視線・時計確認・姿勢
- ドアとの距離

### 面白さ

「待ってあげる」が常に正解ではない。

遠すぎる人を待ち続けると中の人が気まずくなり、早く離すと来ようとしていた人を置いていく。

近づく人が途中で別方向へ曲がる、スマホを見て止まるなど、途中変化を入れられる。

### 強み

- 長押しなのでスマホ操作が直感的
- NPCを見ないと離すタイミングが分からない
- 時間変化が自然にゲーム性になる
- 国や文化による違いも将来的に比較しやすい

### リスク

開ボタンだけだと単調になる可能性がある。主人公の立ち位置や乗員同士の反応を組み合わせる必要がある。

## 3. 候補B：ドア「持っておく？離す？」

### 状況

主人公が店や建物のドアを通った直後。後ろから別の人が来る。

### 主操作

ドアを指で押さえる / ドラッグして開度を維持する / 離す。

### 察する対象

- 相手との距離
- 歩く速さ
- 荷物の有無
- 相手がこちらのドアへ向かっているか
- 待たせることで逆に急がせていないか

### 面白さ

「親切に持つ」が長すぎると、相手が走らされるような空気になる。

短すぎると閉まる。

### 強み

- 操作と現実の行為がほぼ同じ
- 連続量とタイミングの両方がある
- シンプルな背景でPoCを作れる

### リスク

1つの判断軸に見えやすい。複数NPCや途中変化を入れないと浅い。

## 4. 候補C：電車「西日の席 v3」

### 状況

夕方の電車。窓側の人は西日をまぶしそうにしている。一方、子どもは窓の外を見たがっている。

### 主操作

- ブラインドの開度をドラッグ
- 主人公の身体位置を少しずらして光を遮る

### 察する対象

- まぶしそうな人の顔・姿勢
- 子どもの視線
- トンネルや建物による光量変化
- ブラインドをどこまで下げるか

### 面白さ

一人だけを快適にするのではなく、二人の反応を見ながら妥協点を探す。

### 強み

- 連続量の調整が明確
- NPCを見ながら操作する構造を作りやすい
- Riveの連続表情変化を活かしやすい

### リスク

過去プロトタイプで「スライダーを合わせるだけ」に見えた。ブラインド以外の介入や状況変化を入れないと再びゲーム性が弱くなる。

## 6. 現時点の推奨

**候補A「エレベーター」から詳細設計へ進む。**

理由：

- 画面を見ただけで状況が伝わりやすい
- 長押しという身体的操作がある
- NPCの距離・速度・視線を読む必要がある
- 「待つ / 待たない」の二択ではなく、どの時点まで待つかという連続的な判断になる
- 内側と外側の複数利害を同時に扱える
- 状況変化を追加しやすい

ただし、実装前にCritical Reviewを行い、単なる『開ボタン長押しゲーム』になっていないかを確認する。
